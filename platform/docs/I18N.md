# Language packs — operations and authoring guide

YOU HEAL Clinical ships **Spanish (baseline)** and **English (mirror, 100%)**. The contract is
[`CONTRACT.md` §9](CONTRACT.md); this guide is the how-to.

## Model

| Layer | Source of truth | File |
|---|---|---|
| Catalog content (pairs, symptoms, descriptions, protocols…) | Spanish baseline extracted from the guides | `data/catalog/*.json` → `data/i18n/packs/es/catalog.json` |
| Catalog translation | Mirror pack: one entry per baseline field, keyed `<file>/<recordId>/<path>`, carrying `srcHash` of the Spanish it translates | `data/i18n/packs/<loc>/catalog.json` |
| Interface text | One UI pack per language, identical key sets (951 keys) | `data/i18n/packs/<loc>/ui.json` |
| Pack metadata & coverage | Manifest | `data/i18n/packs/<loc>/manifest.json` |
| Reviewed fixes | Committed corrections, applied at merge when `srcHash` still matches | `data/i18n/corrections-<loc>.json` |
| Clinic edits at runtime | Admin overrides in the database (Settings → Language packs) | table `i18n_overrides` |

Packs are embedded into the database by the catalog loader at start-up; no network or external translation
service is ever used. A Spanish correction automatically marks its translation **stale**, and the UI shows the
Spanish original with an **ES** badge until the translation is refreshed.

Entry `status`: `curated` (hand-authored names/labels) · `machine` (model translation, QA-gated, independently
sampled — 0 critical / 0 major) · `reviewed` (edited by a clinic administrator) · `missing` · `stale`.

## Re-translate after Spanish corrections

```sh
node importer/run.js                     # rebuild catalog from the licensed PDFs (+ overrides/supplements)
node importer/i18n/extract.mjs en        # refresh baseline + mirror; queue stale/missing texts in chunks
#   translate data/i18n/_work/en/queue/chunk-NN.json → data/i18n/_work/en/done/chunk-NN.json
#   following data/i18n/STYLE-GUIDE-en.md and the termbase data/i18n/_work/en/termbase.json
node importer/i18n/check-chunk.mjs data/i18n/_work/en/queue/chunk-NN.json data/i18n/_work/en/done/chunk-NN.json
node importer/i18n/apply.mjs en          # merge (QA-gated chunks), corrections, US-spelling normalization, manifest
node tests/web/i18n-keys.mjs             # UI key parity + no hard-coded text
```
Restart the server (or run `npm run catalog:load`); the loader re-embeds changed packs.

## Add a new language (e.g. Portuguese `pt-BR`)

1. `node importer/i18n/extract.mjs pt-BR` — creates the mirror with every entry `missing` and a translation queue.
2. Write `data/i18n/STYLE-GUIDE-pt-BR.md` (copy the English guide's structure and fixed-term table).
3. Translate the queue chunks; every chunk must pass `check-chunk.mjs` with 0 errors.
4. `node importer/i18n/apply.mjs pt-BR`; add `name`/`nativeName`/`dir` for the locale in `apply.mjs` `META`.
5. Copy `data/i18n/packs/en/ui.json` to `data/i18n/packs/pt-BR/ui.json`, translate every value (keys unchanged);
   `node tests/web/i18n-keys.mjs` must pass.
6. Commission an independent bilingual QA sample (stratified, ≥ 250 entries + all recommendation bodies and
   contraindications) before release; record results in `TRANSLATION-NOTES-<loc>.md`.
7. Restart: the language appears automatically in every language menu, the patient "Preferred language" list and
   the report language selector. Right-to-left languages set `"dir": "rtl"` in the manifest.

## Clinical review workflow

`data/i18n/TRANSLATION-NOTES-en.md` lists ~45 Spanish source texts with probable errors found during translation
(e.g. oliguria quantity, hand-washing "before" vs "after", dysphagia/odynophagia, PDF-garbled lists). Correct
them in the **Spanish baseline** (source overrides in `importer/overrides.json`, then `node importer/run.js`); the
English entries become stale and are re-queued by `extract.mjs`. Clinic administrators can also correct an
English text in place (Settings → Language packs → edit); the edit is audited by key only and survives reloads.
